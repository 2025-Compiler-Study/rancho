## 컴퍼일러란?
번역기
A -> B
A로 된 것을 B로 번역해서
B만 아는 사람도 이해할 수 있도록 함
A가 사람이 쓰는 말이라면 B는 컴퓨터가 쓰는 말
사람이 쓰는 말을 컴퓨터가 이해할 수 있도록 번역

## 컴파일러는 글자로 나무를 만듦

listener는 나무를 보다가 어떤 장소에 오면 나를 불러줘하는 역할

## 나무는 누가 돌아다니는가?
가이드(컴파일러)가 나무를 돌아다님
- 위에서 아래로
- 왼쪽부터 차례대로

- e.g)
  - 지금 더하기가 들어왔네
  - 이제 사과 다봤어
  - 이제 바나나 끝

## Listener가 하는 것
Listener는 옆에서 듣다가 말하는 것
- 아 더하기에 들어왔구나 (enter)
- 사과 끝났네
- 바나나 끝났네
callback function 역할
e.g) 
- 사과가 몇개인지 세기
- 바나나가 몇개인지 세기
- 다 끝나면 이제 더하면 돼하고 말하기

## Listener가 좋은 이유
- 나무(parse tree)를 직접 돌아다닐 필요 없음
- 들어왔어, 끝났어만 듣고 말하면 됨
- 복잡하지 않음

## 유치원 버젼 요약
- 컴파일러: 번역기
- 나무: 그림
- Listener: 잘 듣는 친구
- 들어왔어 -> 시작
- 끝났어 -> 마무리


## 컴파일러에서 나무 구조를 쓰는 이유
1. 글은 길고 헷갈림
"사과 더하기 바나나 곱하기 포도"
=> 무엇부터 해야할지 알 수 없음

2. 그래서 글자 말고 그림으로 그림
  더하기
  /    \
사과   곱하기
     /     \
   바나나   포도

3. 나무 그림에는 약속이 있다.
- 위에 있는 것은 나중에
- 아래 있는 것은 먼저
- 가지는 짝을 맞추어서
=> 컴파일러가 말하는 것
"바나나랑 포도를 먼저 곱하고 그 다음에 사과를 더하면 되는구나"

4. 나무가 좋은 이유
- 순서가 보인다.
- 헷갈리지 않는다.
- 길을 잃을 일이 없다.
  - 정해진 구조에서 따라가면 됨

5. Listener와도 잘 어울림
나무가 있으니까, 여기 들어오면 끝, 여기 나가면 끝
Listener는 응 나 들어어 하고 자기 일을 함

Listener에 들어갈때, 나갈때 할 동작을 적어두면 알아서 확인함
들어갈 때 확인해야할 것, 나갈 떄 확인해야할 것을 기록해두면 
하고자하는 작업을 진행할 수 있음

## Listener 중학생 버젼 설명

1. Parser
문법 규칙에 따라
파스트리 생성
구조만 생성!

2. Tree Walker
파스트리 탐색
정해진 순서로 방문

3. Listener 
워커가 알려주는 신호를 듣고 그때 그때 필요한 일을 함


## Listener 듣다의 의미
- enterX: 어떤 문법 구조에 들어갈 때
- exitX: 어떤 문법 구조가 끝났을 때

어떤 식이 시작되면 -> 기록 시작
식이 끝나면 -> 결과정리
### 예제
  +
 / \
1   2

방문순서
1. +에 들어감 => enter
2. 1처리
3. 2처리
4. +  끝남 => exit

Listener는 이 과정에서
숫자를 만나면 저장
연산이 끝나면 계산하거나 정리


### Listener특징
#### 할 수 있는 것
- 구조를 보면서 정보 수집
- 규칙 검사
- AST 생성
- 심볼 테이블 관리

#### 할 수 없는 것
- 방문 순서 변경
- 값을 return해서 위로 전달
- 트리 구조 변경

## 고등학생 버젼

### 1. Listener의 정의 
- Listener는 Parse Tree를 직접 순회하지 않고,
트리 순회 과정에서 발생하는 이벤트에 반응하는 처리 방식이다.
Listener는 컴파일러의 "주체"가 아니라 
콜백(callback)을 제공하는 객체다.

### 2. 컴파일러 처리 흐름

Source code
-> Lexer (토큰 생성)
-> Parser (Parse Tree 생성)
-> Parse Tree Walker (트리 순회)
-> Listener (이벤트 처리)

#### 중요한 점
- parser는 트리를 만든다.
- tree walker 트리를 걷는다.
- listener 걷는 과정에서 호출된다.

### 3. Listener가 호출되는 시점
Parse Tree의 각 노드는 두 시점을 가진다.
- enter 노드에 진입할 때
- exit 노드처리가 끝났을 때

walker는 DFS방식으로 트리를 순회하며 각 노드에서 Listener의 메서드를 호출

#### 4. 예제
a + b * c

  +
 / \
a   *
   /  \
  b    c

방문순서(DFS):
1. enter(+)
2. enter(a) -> exit(a)
3. enter(*)
4. enter(b) -> exit(b)
5. enter(c) -> exit(c)
6. exit(*)
7. exit(+)
#### 연산자부터 순회하는 이유, 피연산자는 바로 enter, exit되는 것처럼 보이는 이유

- 연산자가 부모노드를 차지함
- DFS로 진행되므로 연산자가 먼저 방문되게 됨
- 부모노드는 자식노드 다 방문하고 exit됨
- 단말노드는 enter되고 방문할 다른 자식노드가 없으므로 바로 exit되게 됨
- a + b *c 의 경우 항이 적어서 단말노드에는 피연산자만 있으므로 그렇게 보이게됨
