# Calc3 학습 체크리스트

## 0. 학습 목표
- Calc2 실행기 위에 `read`/`write` 입출력을 안전하게 확장한다.
- 문법 제약(특히 `read()`는 할당문에서만 허용)을 구현으로 보장한다.
- 인터프리터를 CLI 실행 흐름(소스 파일 + stdin/stdout)까지 연결한다.

## 1. Calc3 필수 학습 체크리스트

### A. 문법 이해
- [ ] `stmt`에 `ReadAssign`, `Write`, `IfElse`, `ExprAssign`이 포함됨을 설명할 수 있다.
- [ ] `read()`는 `VAR = read();` 형태로만 가능하고 수식의 일부가 될 수 없음을 이해한다.
- [ ] `write(expr);`는 값을 출력만 하고 반환값이 없음을 이해한다.

### B. 실행기 구현
- [ ] `visitReadAssign`에서 stdin에서 정수 1개를 읽어 변수에 저장한다.
- [ ] 입력 실패(EOF/숫자 아님) 정책을 명확히 정하고 코드에 반영한다.
- [ ] `visitWrite`에서 `expr` 계산 결과를 stdout으로 출력한다.
- [ ] Calc2의 기존 규칙(미정의 변수=0, if/else 실행, 전역 메모리 공유)을 유지한다.

### C. I/O 동작 검증
- [ ] Hello world 성격의 고정값 출력(`write(42);`)이 동작한다.
- [ ] Echo 성격 입력-즉시출력(`a=read(); write(a);`)이 동작한다.
- [ ] 분기와 I/O를 함께 쓰는 프로그램이 의도대로 동작한다.

### D. CLI 연결
- [ ] `calc3 <source-file>` 형태로 소스 파일을 읽어 실행한다.
- [ ] 프로그램 입력은 stdin, 출력은 stdout으로 연결한다.
- [ ] 실행 실패 시 종료 코드/에러 메시지 정책을 정한다.

### E. 테스트
- [ ] 단위 테스트: `expr`, `cond`, `stmt`별 핵심 케이스
- [ ] 통합 테스트: 파일 입력 + stdin 제공 + stdout 비교
- [ ] 회귀 테스트: Calc2 동작이 Calc3에서 깨지지 않음을 확인

### F. 완료 기준
- [ ] Calc3 예제 프로그램 3개 이상을 자동 테스트로 통과한다.
- [ ] I/O 실패 정책이 테스트에 명시되어 있다.
- [ ] 파싱 오류/런타임 오류/입력 오류를 구분해 설명할 수 있다.

## 2. Calc3 이상으로 배우는 확장 체크리스트
- [ ] `write` 출력 버퍼를 분리해 테스트에서 문자열로 검증한다.
- [ ] `read`/`write`를 내장함수 테이블로 추상화해 확장 가능 구조로 바꾼다.
- [ ] AST 계층을 도입해 파서 의존도를 낮춘다.
- [ ] 정적 분석(정의 전 사용, 도달 불가능 분기)을 별도 패스로 구현한다.
- [ ] 실행 트레이스(문장 단위 메모리 변화)를 옵션으로 출력한다.

## 3. 추천 학습 순서
1. Calc2 테스트 안정화
2. 문법에 `read/write` 반영
3. Visitor에 `ReadAssign`, `Write` 추가
4. CLI 러너 구현
5. 통합 테스트 + 오류 정책 고정
