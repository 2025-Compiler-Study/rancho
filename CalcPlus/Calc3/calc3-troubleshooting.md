# Calc3 문제 주의사항과 해결방법

## 1. `read()` 위치 오류
- 문제: `read()`를 수식 내부(`a = read() + 1;`)에서 쓰려고 하면 파싱이 실패한다.
- 원인: 문법상 `read()`는 `VAR = read();` 형태(`ReadAssign`)만 허용된다.
- 해결: 입력은 먼저 변수에 담고, 이후 수식에서 변수를 사용한다.
```calc
a = read();
b = a + 1;
```

## 2. `write()`를 값 반환 함수로 오해
- 문제: `c = write(a);`처럼 사용하려고 하면 문법/의도 모두 맞지 않는다.
- 원인: `write(expr);`는 출력 전용 문장이다.
- 해결: 계산은 `expr`에서 끝내고, 출력은 별도 문장으로 분리한다.

## 3. 미정의 변수 처리
- 문제: 초기화되지 않은 변수를 읽을 때 런타임 오류가 날 수 있다.
- 원인: 변수 테이블 조회 시 기본값 정책이 없으면 KeyError가 발생한다.
- 해결: Visitor에서 미정의 변수는 `0`으로 자동 초기화한다.

## 4. 연산자 우선순위 혼동
- 문제: `1 + 2 * 3` 결과가 기대와 다르게 나올 수 있다.
- 원인: Visitor에서 재귀식 `expr` 처리 순서를 잘못 구현하면 우선순위가 깨진다.
- 해결: `visitMulDiv`, `visitAddSub`, `visitParens`를 분리해 각각 정확히 계산한다.

## 5. `if/else` 블록 실행 누락
- 문제: 조건문이 있어도 내부 문장이 실행되지 않거나 양쪽이 모두 실행된다.
- 원인: `thenBlock`, `elseBlock` 분기를 명확히 나누지 않았거나 `else` 존재 체크가 빠졌다.
- 해결: 조건 참/거짓에 따라 한쪽 블록만 방문하고, `elseBlock is not None`을 검사한다.

## 6. 입력 실패(EOF/비정수) 정책 부재
- 문제: 자동 테스트나 파이프 입력에서 프로그램이 예외로 종료된다.
- 원인: `read()` 실패 시 처리 규칙이 없음.
- 해결: 정책을 고정한다. 현재 구현은 EOF/빈 문자열/비정수를 `0`으로 처리한다.

## 7. 테스트에서 출력 검증 어려움
- 문제: `stdout`만 사용하면 단위 테스트에서 검증이 불편하다.
- 원인: 출력이 외부 부수효과로만 존재함.
- 해결: Visitor 내부에 `outputs` 버퍼를 두고, `write()` 시 `outputs.append(value)`를 함께 수행한다.

## 구현 체크포인트
1. `visitCalc3`: 문장 순서대로 실행 후 최종 `env` 반환
2. `visitExprAssign`/`visitReadAssign`: 변수 저장
3. `visitCond`: 비교 연산자 6종 처리
4. `visitMulDiv`/`visitAddSub`: 사칙연산 처리
5. `visitVar`: 미정의 변수 기본값 `0`
6. `visitWrite`: `stdout` 출력 + `outputs` 버퍼 누적
