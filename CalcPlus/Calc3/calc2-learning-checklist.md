# Calc2 학습 체크리스트

## 0. 학습 목표
- Calc2를 Visitor 기반 인터프리터로 안정적으로 구현한다.
- 문법(ANTLR)과 시맨틱(실행 로직)을 분리해서 설명할 수 있다.
- 테스트로 언어 동작을 검증하는 습관을 갖는다.

## 1. Calc2 필수 학습 체크리스트

### A. 문법 이해
- [ ] `CalcPlus.g4`에서 `stmt`, `cond`, `block`, `expr`의 역할을 설명할 수 있다.
- [ ] `if (cond) { ... } else { ... }`에서 `else`가 선택사항임을 설명할 수 있다.
- [ ] 비교 연산자 6종(`==`, `!=`, `<`, `>`, `<=`, `>=`)이 조건식에만 쓰인다는 점을 이해한다.

### B. 실행기(Visitor) 구현
- [ ] `visitCalc2`에서 문장(`stmt`)을 순서대로 실행한다.
- [ ] `visitExprAssign`에서 RHS 계산 후 변수 메모리에 저장한다.
- [ ] `visitIfElse`에서 조건 참/거짓에 따라 정확히 한 블록만 실행한다.
- [ ] `visitBlock`에서 블록 내부 문장을 순차 실행한다.
- [ ] 미정의 변수 접근 시 `0`으로 처리한다.

### C. 계산 규칙 검증
- [ ] 사칙연산 우선순위가 올바르다(`*`,`/` 우선).
- [ ] 괄호가 우선순위를 강제한다.
- [ ] 조건식에서 좌/우 식을 먼저 계산한 뒤 비교한다.
- [ ] 분기문에 블록 스코프를 도입하지 않았음을 검증한다(전역 메모리 공유).

### D. 테스트
- [ ] then 블록만 실행되는 케이스
- [ ] else 블록만 실행되는 케이스
- [ ] else 생략 + 조건 false 케이스
- [ ] 미정의 변수가 조건식/수식에 등장하는 케이스
- [ ] 비교 연산자 6종 각각의 참/거짓 케이스

### E. 완료 기준
- [ ] `test_calc2.py` 전부 통과
- [ ] 임의 프로그램 3개를 직접 만들어 실행 결과를 설명 가능
- [ ] "왜 이 결과가 나왔는지"를 파스트리 순회 관점에서 설명 가능

## 2. Calc2 이상으로 배우는 확장 체크리스트

### A. 구조 확장
- [ ] ParseTree 직접 실행 대신 `AST` 계층을 도입해 본다.
- [ ] `Parser -> AST 생성 -> AST 실행` 2단계 구조를 구현한다.
- [ ] 실행기와 정적분석기를 분리한다(하나의 트리, 두 개의 패스).

### B. 정적 분석
- [ ] 정의 전 사용(Use-before-define) 경고를 구현한다.
- [ ] 경고에 line/column 정보를 포함한다.
- [ ] 경고와 실행 결과를 분리 출력하도록 설계한다.

### C. 언어 설계 실험
- [ ] 블록 스코프 버전을 추가해 전역 스코프 버전과 동작 차이를 비교한다.
- [ ] 0-기본값 정책 대신 런타임 오류 정책을 실험한다.
- [ ] 나눗셈 결과 정책(int/float/오류)을 명시하고 테스트로 고정한다.

### D. 품질/운영 관점
- [ ] 에러 메시지 포맷을 통일한다.
- [ ] 회귀 테스트를 추가해 변경 시 동작이 깨지지 않게 한다.
- [ ] 최소 CLI 러너를 만들어 `source` 파일 실행을 자동화한다.

## 3. 추천 학습 순서 (짧은 플랜)
1. 문법/시맨틱 계약표 작성  
2. Visitor 구현 고정  
3. 테스트로 규칙 봉인  
4. 정적분석 패스 추가  
5. AST/스코프/오류정책 실험
