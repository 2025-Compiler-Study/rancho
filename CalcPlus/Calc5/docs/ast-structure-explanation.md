# Calc5 AST 구조가 이렇게 만들어지는 이유

## 대상 expression

```text
5 * 3 + a * (5 - 9 / 3)
```

연산 우선순위와 괄호를 명확하게 표시하면 다음과 같다.

```text
(5 * 3) + (a * (5 - (9 / 3)))
```

AST는 소스 코드를 문자 그대로 복사하는 트리가 아니다. 어떤 값을 먼저 만들고, 그 결과를 어떤 연산이 사용하는지 나타내는 의미 중심 트리다.

## 기본 원리

이항 연산은 다음 형태다.

```text
left operator right
```

AST에서는 연산자가 부모가 되고, 왼쪽과 오른쪽 피연산자가 자식이 된다.

```text
    operator
     /    \
  left    right
```

코드에서는 다음 노드로 표현한다.

```python
BinaryExpr(operator, left, right)
```

숫자와 변수는 더 계산할 자식이 없으므로 leaf node가 된다.

```python
IntLiteral(5)
VarRef("a")
```

## 단계별 AST 구성

### 1. 전체 루트 결정

전체 expression에서 가장 마지막에 적용되는 연산은 `+`다.

```text
왼쪽 결과 + 오른쪽 결과
```

따라서 `+`가 AST의 루트가 된다.

```text
        +
       / \
  왼쪽 결과  오른쪽 결과
```

AST의 루트는 소스에서 가장 먼저 등장한 연산자가 아니라, 자식들의 결과를 받아 가장 마지막에 적용되는 연산자다.

### 2. 왼쪽 subtree

루트 `+`의 왼쪽은 `5 * 3`이다. `*`는 두 값 `5`, `3`을 사용한다.

```text
    *
   / \
  5   3
```

코드로는 다음과 같다.

```python
BinaryExpr(
    "*",
    IntLiteral(5),
    IntLiteral(3),
)
```

### 3. 오른쪽 subtree

루트 `+`의 오른쪽은 다음 expression이다.

```text
a * (5 - 9 / 3)
```

이 부분에서 가장 마지막에 적용되는 연산은 `*`이므로 `*`가 subtree의 부모가 된다.

```text
      *
     / \
    a   5 - 9 / 3
```

왼쪽 자식은 변수 `a`, 오른쪽 자식은 괄호 내부 expression이다.

### 4. 괄호 내부 subtree

괄호 내부는 다음과 같다.

```text
5 - 9 / 3
```

`/`는 `-`보다 우선순위가 높으므로 실제 그룹은 다음과 같다.

```text
5 - (9 / 3)
```

먼저 `9 / 3`이 subtree가 된다.

```text
    /
   / \
  9   3
```

그 결과가 뺄셈의 오른쪽 값으로 사용된다.

```text
      -
     / \
    5   /
       / \
      9   3
```

### 5. 전체 연결

각 subtree를 연결하면 최종 AST가 된다.

```text
              +
           /     \
          *       *
        /  \     /  \
       5    3   a    -
                   /   \
                  5     /
                       / \
                      9   3
```

코드로 표현하면 다음과 같다.

```python
BinaryExpr(
    "+",
    BinaryExpr(
        "*",
        IntLiteral(5),
        IntLiteral(3),
    ),
    BinaryExpr(
        "*",
        VarRef("a"),
        BinaryExpr(
            "-",
            IntLiteral(5),
            BinaryExpr(
                "/",
                IntLiteral(9),
                IntLiteral(3),
            ),
        ),
    ),
)
```

## 자식이 부모보다 먼저 계산되는 이유

부모 연산자는 자식의 결과에 의존한다.

예를 들어 `5 - 9 / 3`에서 `-`를 실행하려면 오른쪽 값인 `9 / 3`의 결과가 먼저 필요하다.

```text
9 / 3 = 3
5 - 3 = 2
```

따라서 먼저 처리해야 하는 연산이 트리 아래에 있고, 그 결과를 사용하는 연산이 위에 있다.

재귀 계산은 다음 순서를 따른다.

```text
왼쪽 자식 계산
-> 오른쪽 자식 계산
-> 부모 연산 적용
```

`a = 4`일 때 전체 계산은 다음과 같다.

```text
5 * 3  = 15
9 / 3  = 3
5 - 3  = 2
4 * 2  = 8
15 + 8 = 23
```

## 괄호 노드가 없는 이유

ANTLR Parse Tree에는 소스 문법을 표현하기 위해 괄호가 남아 있다.

```text
Parens
├── '('
├── expression
└── ')'
```

AST에서는 괄호가 만든 그룹이 부모와 자식의 연결 관계에 이미 반영되므로 괄호 노드를 제거한다.

```python
def visitParens(self, ctx):
    return self.visit(ctx.expr())
```

다음 두 expression은 괄호 노드 없이도 서로 다른 트리가 된다.

```text
1 + 2 * 3             (1 + 2) * 3

    +                       *
   / \                     / \
  1   *                   +   3
     / \                 / \
    2   3               1   2
```

왼쪽 트리는 `2 * 3`을 먼저 계산한다. 오른쪽 트리는 `1 + 2`를 먼저 계산한다. 괄호 문자는 없어졌지만 괄호가 결정한 의미는 AST 모양에 남아 있다.

## 어떤 종류의 트리인가

현재 expression에서 사용하는 `+`, `-`, `*`, `/`는 모두 피연산자 두 개를 받는 이항 연산자다. 따라서 각 `BinaryExpr`는 `left`, `right` 두 자식을 가진다.

| 분류 | 해당 여부 | 이유 |
| --- | --- | --- |
| 이진 트리 | 해당 | 각 연산 노드가 최대 두 자식을 가짐 |
| 모든 내부 노드가 자식 둘인 트리 | 해당 | 현재 연산자가 모두 이항 연산자임 |
| 완전 이진 트리 | 해당하지 않음 | 마지막 레벨이 왼쪽부터 채워지는 구조가 아님 |
| 균형 이진 트리 | 보장하지 않음 | 우선순위와 괄호에 따라 한쪽이 깊어질 수 있음 |
| 이진 탐색 트리 | 해당하지 않음 | 값의 크기로 자식 위치를 정하지 않음 |

이진 트리인 것은 현재 expression subtree에 대한 성질이다. 나중에 `Program`이나 `Block`이 여러 statement를 자식으로 가지면 AST 전체는 일반 트리가 된다.

## left와 right를 구분하는 이유

피연산자의 순서는 expression 의미의 일부다.

```python
BinaryExpr("-", IntLiteral(5), IntLiteral(3))  # 5 - 3
BinaryExpr("-", IntLiteral(3), IntLiteral(5))  # 3 - 5
```

뺄셈과 나눗셈은 자식 순서를 바꾸면 결과가 달라진다. 따라서 AST와 비주얼라이저 모두 간선을 `left`, `right`로 구분한다.

## Parse Tree와 AST의 차이

Parse Tree는 문법이 입력을 어떻게 인식했는지 자세히 보관한다.

```text
괄호
문법 중간 규칙
연산자 토큰
정수 토큰
변수 토큰
```

AST는 실행과 분석에 필요한 의미만 보관한다.

```text
IntLiteral
VarRef
BinaryExpr
```

따라서 Parse Tree에서 AST로 변환할 때 괄호와 문법용 중간 노드는 사라지고, 연산 우선순위와 계산 의존 관계는 트리 구조로 남는다.

## 핵심 정리

AST 모양은 다음 세 가지가 결정한다.

1. 연산자 우선순위
2. 괄호가 만드는 그룹
3. 연산 결과의 의존 관계

먼저 계산할 연산은 자식이 되고, 그 결과를 사용하는 연산은 부모가 된다. 따라서 이 AST는 단순한 그림이 아니라 재귀적으로 실행할 수 있는 프로그램의 의미 구조다.
