# Issue Workflow

앞으로 이 디렉터리에서 작업할 때는 먼저 이슈를 만든 뒤 진행한다.

## 기본 원칙

1. 작업 시작 전에 이슈를 먼저 만든다.
2. 구현 범위와 완료 조건은 이슈 본문에 짧게 적는다.
3. 커밋 메시지와 작업 내용은 가능한 한 해당 이슈와 연결되게 유지한다.
4. 작업이 끝나면 이슈 기준으로 변경 사항을 정리한다.

## 기본 흐름

1. 이슈 생성
2. 이슈 범위 확인
3. 구현 또는 문서 작업 진행
4. 테스트 수행
5. 커밋
6. 푸시

## Calc4 현재 작업에 적용

- `Calc4` 초기 테스트 환경 구성 같은 작업도 다음부터는 이슈를 먼저 만든다.
- 구현 전 스캐폴딩, 테스트 추가, 문법 수정도 각각 이슈 단위로 나눌 수 있다.
