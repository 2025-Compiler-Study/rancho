# Issue Workflow

앞으로 이 디렉터리에서 작업할 때는 아래 순서를 기본 흐름으로 사용한다.

`issue -> branch -> commit -> push -> PR -> merge`

## 기본 원칙

1. 작업 시작 전에 이슈를 먼저 만든다.
2. 구현 범위와 완료 조건은 이슈 본문에 짧게 적는다.
3. 작업은 해당 이슈 전용 브랜치에서 진행한다.
4. 커밋 메시지와 작업 내용은 가능한 한 해당 이슈와 연결되게 유지한다.
5. 작업이 끝나면 푸시 후 PR을 만들고, 검토가 끝나면 merge 한다.

## 기본 흐름

1. 이슈 생성
2. 브랜치 생성
3. 구현 또는 문서 작업 진행
4. 테스트 수행
5. 커밋
6. 푸시
7. PR 생성
8. Merge

## Calc4 현재 작업에 적용

- `Calc4` 관련 작업은 `main`에서 바로 하지 않는다.
- 구현 전 스캐폴딩, 테스트 추가, 문법 수정도 각각 이슈와 브랜치 단위로 나눈다.
