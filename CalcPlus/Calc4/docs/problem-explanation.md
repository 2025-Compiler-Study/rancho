# Calc4 Problem Explanation

이 문서는 `subject.md`의 Calc-4 과제를 구현 관점에서 다시 풀어쓴 해설이다.

## 한 줄 요약

Calc4는 기존 계산기 언어에 `변수 선언`, `블록 스코프`, `섀도잉`을 추가한 인터프리터 과제다.

즉, 이제부터는 변수 이름만 보고 바로 값을 쓰는 것이 아니라:

- 먼저 선언되었는지 확인해야 하고
- 현재 블록에서 유효한지 확인해야 하며
- 같은 이름이 내부 블록에서 다시 선언되면 그 변수를 우선 사용해야 한다

## 문제의 핵심 변화

이전 단계와 비교했을 때 Calc4의 본질적인 변화는 두 가지다.

1. 변수를 사용하기 전에 반드시 선언해야 한다.
2. 변수의 유효 범위가 프로그램 전체가 아니라 블록 단위가 된다.

문법 차원에서는 아래 두 문장이 새로 중요해진다.

```c
int a, b;
{
  ...
}
```

첫 번째는 선언문이고, 두 번째는 독립적인 블록 문장이다.

## 문법을 어떻게 읽어야 하는가

Calc4 문법에서 중요한 부분은 `stmt`와 `block`이다.

```antlrv4
stmt    :   VAR '=' expr ';'                    # ExprAssign
        |   VAR '=' 'read' '(' ')' ';'          # ReadAssign
        |   'if' '(' cond ')' thenBlock=block
            ('else' elseBlock=block)?           # IfElse
        |   'write' '(' expr ')' ';'            # Write
        |   'int' VAR (',' VAR)* ';'            # Declare
        |   block                               # StmtBlock
        ;

block   :   '{' (stmt)* '}' ;
```

여기서 해석 포인트는 다음과 같다.

- 선언문 `Declare`는 문장이다.
- 블록 자체도 문장 `StmtBlock`이다.
- 블록 안에는 다시 여러 `stmt`가 들어간다.
- 따라서 블록은 재귀적으로 중첩될 수 있다.

이 구조 때문에 구현도 자연스럽게 재귀 순회와 스코프 스택으로 연결된다.

## 구현 과제 #1의 의미

구현 과제 #1은 아직 블록 전체를 완성하라는 뜻이 아니다.  
먼저 "선언된 변수만 쓸 수 있는 상태"를 만드는 단계다.

이 단계에서 반드시 맞춰야 하는 규칙은 아래와 같다.

1. `int a;`를 만나면 변수 `a`가 생성되고 값은 `0`이 된다.
2. 선언되지 않은 변수에 대입하면 에러다.
3. 선언되지 않은 변수를 수식에서 읽으면 에러다.
4. 같은 스코프에서 같은 이름을 다시 선언하면 에러다.

즉, 이 단계의 핵심은 스코프 전체가 아니라 "선언 여부를 강제하는 심볼 테이블"이다.

예:

```c
int a;
write(a);   // 가능, 0
```

```c
a = 3;      // 불가, 선언 전 대입
```

```c
int a;
int a;      // 불가, 같은 스코프 재선언
```

## 구현 과제 #2의 의미

구현 과제 #2에서 비로소 블록 스코프가 완성된다.

추가되는 규칙은 아래와 같다.

1. 블록 안에서 선언한 변수는 블록 밖에서 사용할 수 없다.
2. 내부 블록은 바깥 블록의 변수를 읽고 쓸 수 있다.
3. 내부 블록에서 같은 이름을 선언하면 바깥 변수를 가린다.
4. 내부 블록이 끝나면 가려졌던 바깥 변수가 다시 보인다.

예:

```c
int a;
a = 1;
{
  int a;
  a = 2;
  write(a);   // 2
}
write(a);     // 1
```

이 예제의 핵심은 두 개의 `a`가 서로 다른 변수라는 점이다.

## 왜 스택이 필요한가

블록은 들어갔다가 나온다.  
그리고 가장 안쪽 블록의 변수가 항상 우선한다.

이 특성 때문에 심볼 테이블은 보통 "스코프 스택"으로 구현한다.

예를 들어 아래와 같이 생각하면 된다.

```text
[
  {"a": 1},          # 전역 또는 바깥 블록
  {"a": 2, "b": 3}   # 현재 안쪽 블록
]
```

변수 조회 규칙:

- 스택의 맨 위부터 아래로 찾는다.
- 가장 먼저 찾은 이름을 사용한다.

변수 선언 규칙:

- 맨 위 스코프에서만 중복 여부를 확인한다.
- 맨 위 스코프에만 새 변수를 추가한다.

블록 진입/종료 규칙:

- 블록 시작: 새 스코프 push
- 블록 종료: 현재 스코프 pop

이 구조를 쓰면 섀도잉이 별도 예외 처리 없이 자연스럽게 해결된다.

## 심볼 테이블이 해야 할 일

문제 해설을 코드로 옮기면 `SymbolTable`의 책임은 대략 아래와 같다.

- `push_scope()`: 새 블록 진입
- `pop_scope()`: 블록 종료
- `declare(name)`: 현재 스코프에 변수를 0으로 등록
- `lookup(name)`: 현재 스코프부터 바깥으로 값을 찾음
- `assign(name, value)`: 현재 스코프부터 바깥으로 찾아 값을 변경

검사 기준도 같이 정리하면 다음과 같다.

- `declare(name)`:
  현재 스코프에 이미 있으면 에러
- `lookup(name)`:
  어느 스코프에도 없으면 에러
- `assign(name, value)`:
  어느 스코프에도 없으면 에러

## Visitor는 어디서 무엇을 처리해야 하는가

Visitor 구현은 각 문법 라벨의 의미를 수행하면 된다.

중요한 방문 지점은 다음과 같다.

- `visitDeclare`
- `visitExprAssign`
- `visitVar`
- `visitStmtBlock` 또는 `visitBlock`
- `visitIfElse`
- `visitWrite`
- `visitReadAssign`

가장 먼저 구현할 우선순위는 보통 아래가 안전하다.

1. `visitDeclare`
2. `visitVar`
3. `visitExprAssign`
4. 사칙연산 expression 방문 메서드
5. `visitBlock`
6. `visitStmtBlock`
7. `visitIfElse`
8. `visitWrite`, `visitReadAssign`

이 순서가 좋은 이유는 선언/조회/대입이 먼저 안정되어야 블록과 제어문도 자연스럽게 맞기 때문이다.

## 선언문은 왜 쪼개서 처리하는가

문법상 선언문은 이렇게 한 번에 여러 이름을 받을 수 있다.

```c
int a, b, c;
```

하지만 구현에서는 사실상 아래와 같은 세 번의 선언으로 보는 편이 단순하다.

```text
declare("a")
declare("b")
declare("c")
```

즉, 파스 트리에서는 한 문장이지만 의미적으로는 여러 번의 등록 작업이다.

## 가장 자주 틀리는 규칙

다음은 구현할 때 흔히 헷갈리는 부분이다.

### 1. 선언과 조회의 탐색 범위가 다르다

- 선언은 현재 스코프만 본다.
- 조회와 대입은 현재 스코프부터 바깥까지 본다.

이 차이를 놓치면 섀도잉이 깨진다.

### 2. 선언 직후 값은 0이다

```c
int a;
write(a);   // 에러가 아니라 0
```

### 3. 같은 이름이라도 다른 스코프면 허용된다

```c
int a;
{
  int a;    // 허용
}
```

### 4. 블록이 끝나면 내부 변수는 사라진다

```c
{
  int a;
}
write(a);   // 에러
```

### 5. 섀도잉 중에는 바깥 변수가 안 보인다

```c
int a;
a = 1;
{
  int a;
  write(a); // 0, 바깥 a가 아니라 안쪽 a
}
```

## 예제로 보는 실행 흐름

아래 코드를 보자.

```c
int a;
a = 1;
{
  int a;
  a = a + 1;
  write(a);
}
write(a);
```

실행 흐름은 다음과 같다.

1. 바깥 스코프에서 `a` 선언, 값 `0`
2. 바깥 `a = 1`
3. 블록 진입, 새 스코프 push
4. 안쪽 스코프에서 `a` 선언, 값 `0`
5. `a = a + 1`에서 읽는 `a`는 안쪽 `a`, 결과는 `1`
6. `write(a)`는 `1`
7. 블록 종료, 안쪽 스코프 pop
8. 마지막 `write(a)`는 다시 바깥 `a`, 값은 `1`

출력은 아래와 같다.

```text
1
1
```

이 예제가 중요한 이유는 섀도잉과 선언 직후 0 초기화가 동시에 드러나기 때문이다.

## 요약

Calc4는 "변수 선언을 강제하고, 블록 단위 유효 범위를 도입하는 계산기 언어" 문제다.

핵심 판단 기준은 항상 아래 세 가지다.

1. 이 변수는 현재 시점에 선언되어 있는가
2. 그 선언은 현재 스코프에서 유효한가
3. 같은 이름이 더 안쪽 스코프에서 섀도잉하고 있지는 않은가

이 세 가지를 스코프 스택으로 구현하면 문제의 대부분이 정리된다.
